AI DEV FINAL THREE LAYER - DETAILED MAPPING AUDIT

Date: 2026-06-27
Scope checked: AIDevFinal old project vs AIDevFinalThreeLayer new project.
Execution note: Per request, I did a source-level audit only. I did not run the services.


1. HIGH LEVEL RESULT

The new project is mapped to the old project at the architecture, graph-flow,
node-name, route-boundary, and data-contract level.

The new project is still not a byte-for-byte port of the old JS app, because it
keeps the requested three-layer split and uses Python/FastAPI/LangGraph/Pydantic
inside the orchestrator. After the latest pass, the main agent workflow now uses
the old PM/architect/planner/coder/reviewer/debugger/registry/simplifier/pattern
prompts and the Docker sandbox lifecycle has been ported into Python.

Remaining differences are mostly around operational API/UI features:
checkpoint resume, cancel, sandbox file browser APIs, and old dashboard-derived
event compatibility.

So the correct status is:

- Same three-layer architecture: yes.
- Same top-level graph flow: yes.
- Same agent/node file names: yes.
- Same state-field family: mostly yes, with Pydantic model changes.
- Uniform JSON/SSE data sharing between layers: yes.
- Same internal intelligence as old JS agents: mostly mapped for orchestrator
  agent workflow; operational resume/cancel/file-browser parity still pending.
- Same old server/dashboard capabilities: partial, not full.


2. THREE LAYER ARCHITECTURE MAPPING

Old project:

- React dashboard lived in AIDevFinal/dashboard.
- Node Express server lived in AIDevFinal/server.
- LangGraph, agents, Gemini, Docker sandbox, graph runner, WebSocket bridge all
  lived in the same Node.js application/process.

New project:

- frontend/
  React + Vite dashboard.
  Talks only to the gateway.
  Uses JSON fetch calls and JSON SSE event payloads.

- gateway/
  Node.js + Express API gateway.
  Owns login, user/project metadata, gateway health, SSE/WebSocket relay, and
  JSON calls to the Python AI service.
  It does not run the AI workflow itself.

- orchestrator/
  Python + FastAPI + LangGraph.
  Owns graph execution, Pydantic state validation, Gemini access through
  LangChain/LangGraph-compatible boundaries, Redis checkpoint writes, sandbox
  file writes, and Git snapshots.

- docker-compose.yml
  Starts frontend, gateway, orchestrator, Postgres, and Redis as separate
  services.

This is a correct split for the requested 3-layer architecture.


3. DATA SHARING STYLE

Frontend -> Gateway:

- POST /api/login with JSON.
- GET /api/health with JSON response.
- GET /api/projects?user_id=... with JSON response.
- POST /api/projects with JSON:
  {
    "requirement": "...",
    "user_id": "demo-user",
    "token_budget_usd": 2.0
  }
- GET /api/projects/:projectId/events with SSE frames whose data is JSON.

Gateway -> Orchestrator:

- GET /health with JSON response.
- POST /runs with JSON:
  {
    "requirement": "...",
    "user_id": "...",
    "token_budget_usd": 2.0
  }
- GET /runs/:projectId/events with SSE frames whose data is JSON.

Streaming event shape:

{
  "type": "node.started | node.completed | run.completed | run.failed | heartbeat",
  "node": "pmAgent | coderAgent | graph | ...",
  "message": "...",
  "state": { "...": "AgentState snapshot" }
}

Public API payloads use snake_case where appropriate:

- user_id

7. ORCHESTRATOR NODE-BY-NODE DETAIL

pmAgent:

- Old JS: full PM prompt with Gemini safeCallGemini, token budgeting, questions,
  spec generation, and token delta handling.
- New Python: uses the same PM prompt through safe_call_json_agent, LangChain,
  Gemini, JSON repair/retry, and token/cost tracking. It returns mock JSON only
  when GEMINI_API_KEY or Gemini deps are unavailable.
- Mapping status: prompt and flow mapped.

humanInput:

- Old JS: CLI mode and server InputBridge mode, waits for user answers.
- New Python: records dashboard/API handoff and sets spec_ready if there is a
  userRequirement.
- Mapping status: route exists, but live wait-for-dashboard-input is not fully
  implemented in FastAPI/gateway.

architectAgent:

- Old JS: five Gemini prompt calls for entities, DB schema, APIs, frontend pages,
  folder/dependencies.
- New Python: same five prompt-backed calls, same naming rules, validation
  feedback context, and same blueprint fields.
- Mapping status: prompt and flow mapped.

blueprintValidator:

- Old JS: detailed validation of tables, entity-table matching, foreign keys,
  endpoint/table consistency, frontend API calls, auth/page mismatch, and
  warnings/errors with fix targets.
- New Python: implements core checks for entity tables, foreign keys, endpoint
  table references, frontend API calls, and auth mismatch.
- Mapping status: close structurally, simpler internally.

plannerAgent:

- Old JS: Gemini generates detailed phased plan from blueprint and spec.
- New Python: same Planner Agent prompt, scaffold-awareness rules, mandatory
  phase order, and taskQueue shape.
- Mapping status: prompt and flow mapped.

setupSandbox:

- Old JS: creates sandbox folders, scaffold files, .env files, Git repo, Docker
  network, DB/backend/frontend containers, installs npm dependencies, creates DB
  tables.
- New Python: services/sandbox.py ports the same folder/scaffold/.env/Git/Docker
  network/container/npm install/table creation behavior, then setupSandbox seeds
  the scaffold registry.
- Mapping status: core Docker sandbox behavior mapped.

sandboxHealthCheck:

- Old JS: checks sandbox record, folder structure, package files, Git, DB
  container, backend container, frontend container.
- New Python: checks the same categories through services/sandbox.py, with a
  local-only fallback when Docker is unavailable.
- Mapping status: mapped with fallback behavior.

selectNextTask:

- Old JS: selects next pending task, moves to phase verification after all phase
  tasks are done, moves to done after all work.
- New Python: same logic shape.
- Mapping status: closely mapped.

contextBuilder:

- Old JS: builds rich context from registry, dependencies, related files,
  relevant DB tables, API endpoints, templates, and estimated token size.
- New Python: now ports exact/fuzzy/disk dependency lookup, convention-based

coderAgent:

- Old JS: uses Gemini prompts for backend/frontend file generation, retry

updateRegistry:

- Mapping status: behavior mapped.

reviewerAgent:

- New Python: uses the same reviewer prompt/checklist with project patterns and

- Mapping status: behavior mapped.

executorAgent:

humanEscalation:

12. REDIS / CHECKPOINTING MAPPING

Old JS:

- createCheckpointer returns RedisSaver if available, otherwise MemorySaver.
- LangGraph checkpointer is integrated into graph.compile.
- CLI resume uses graph.getState and graph.invoke(null, config).

New Python:

- workflow.py runs StateGraph and calls checkpoint_state after each node.
- checkpoint_state writes:
  checkpoint:{project_id}:{node_name}
  and appends keys to:
  checkpoints:{project_id}
- Event bus keeps in-memory event streams for SSE.

Important difference:

- New Redis checkpointing is custom per-node state persistence, not LangGraph's
  native RedisSaver checkpointer.
- Resume from checkpoint is not implemented yet in FastAPI/gateway.

15. FINAL AUDIT SUMMARY

The new folder correctly follows the requested three-layer architecture:

Frontend -> Gateway -> Orchestrator

The data passing between layers is uniform:

JSON for HTTP, JSON payloads inside SSE/WebSocket events for streaming.

The graph and file naming are mapped to the old project:

Same node names, same main graph route targets, same major state fields.

Implementation depth after the latest pass:

The orchestrator now maps the old rich Node/Gemini/Docker runtime for the main
agent workflow: PM, architect, planner, context building, coding, registry,
review, execution, debugging, simplification, pattern extraction, Docker
sandboxing, Git snapshots, and rollback are now prompt-backed or behaviorally
ported into Python/LangGraph/Pydantic.

The remaining differences are mostly around gateway/frontend operational
features: resume, cancel, sandbox file APIs, derived event compatibility, and
reconnecting sandbox metadata across orchestrator restarts.
